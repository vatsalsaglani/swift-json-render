# JSON Render for Swift

<Callout kind="decision" title="Decision summary">
Build `swift-json-render` (github.com/vatsalsaglani/swift-json-render, Apache-2.0): a native SwiftUI implementation of the json-render spec (core 0.22.0) with streaming and nesting first-class, a theme and component-injection layer, 15 chart components, an optional composer on the OpenAI Decisions API, an optional consent-gated remote image loader, two shipped skills, and a Rafu catalog on top. Borrow the `@Component` macro and `JSONValue` / `JSONPointer` ideas from rxtech-lab/json-render-swift with credit; no dependency on it. No web view, no JavaScript, no code evaluation.
</Callout>

## 1. Thesis and the user's words

> "Can we think of adding this somewhere? https://github.com/vercel-labs/json-render — If a user says show me something then we can use some custom from here and load it on canvas; only thing we might have to use web view which would take more memory. Anything custom in Swift with a parity to this and then we can open source that package as well."

> "What all components are supported in JSON Render and I think it's a skill and set of components we'd need to add the same with Rafu. Let's list those down and see what other Swift libraries have and should we build on top of them instead of reinventing the wheel given we can pass our custom theme components as well."

> "Streaming, nesting — all of these things should be there."

> "Let's focus on making these look spectacularly simple and highly customisable."

Thesis: a model that answers "show me failing tests by suite" should put a native card on the Ensemble board, not an HTML page in a web view. json-render defines a small, flat, streamable JSON grammar for exactly this. We implement that grammar in Swift, keep the spec identical so upstream prompts, skills, fixtures and MCP ideas carry over, and render it with SwiftUI so a card costs kilobytes.

## 2. Headline principle: spectacularly simple, highly customisable

### 2.1 Simple by default

| Instead of | Do |
|---|---|
| Eight to twelve props per component | Three to five; only the content prop required; styling from the theme |
| Colour as decoration | Colour only for meaning: the accent on one primary action; status hues with an icon and a word |
| Mixed radii, shadows inside cards, borders everywhere | One radius scale (4 / 7 / 12 pt); no shadow in a card; a hairline only where a surface starts |
| Five font sizes in one card | One scale 11 / 12 / 13 / 15 / 20 / 28 pt, system font, tabular digits in data |
| Spinners, shimmer, layout jumps | Static redacted placeholders that hold the final layout; a slow fade, none under Reduce Motion |
| Cramped padding | 12 pt card padding, 10 pt stack gap, 20 pt between sections |
| Clever component names | json-render's own names, so upstream prompts and skills transfer |
| Every number a chart | Stat for one number, Table for rows, a chart for a series, Funnel for stages, Treemap for many parts |

Default-look gallery (Card, Stat row, Table, Tabs, form, Alert, Chart) in both themes: HTML page, section 2.1.

### 2.2 Customisable in layers (least to most effort)

| Layer | Changes | API |
|---|---|---|
| a. Theme tokens | colour roles, type scale, spacing, radius, elevation, motion | `JSONRenderTheme` environment; presets `.native`, `.rafuIndigo`, `.rafuKhadi`, `.highContrast`; `.jsonRenderTheme(_:)`, `.jsonRenderTheme(\.radius.card, 6)`, per-type subtree override |
| b. Variants and sizes | model-selectable looks declared in the catalog | Button `primary / secondary / destructive / plain`, `sm / md / lg`; Card `plain / outlined / elevated` |
| c. Style hooks | a SwiftUI style protocol per component | `JRCardStyle`, `JRTableStyle`, `JRStatStyle`, `BarChartStyle` … `.jrCardStyle(RafuCardStyle())` |
| d. Slots | named child regions | `slots: header / footer / leading / trailing / empty / loading / error` (+ `title / caption / tooltip / center` on charts) |
| e. View replacement | one type, same props and actions | `catalog.override("Table") { ctx in MyTable(ctx) }` |
| f. Custom components and actions | new types | `@JRComponent("Stat") struct … { @JRProp var label: String }`, `catalog.action("open_file") { params, host in … }` |

Rule: customisation never changes semantics. The parity suite runs once per preset and once with every type overridden by a stub and asserts identical state transitions and emitted actions.

### 2.3 Measurable

Default tokens (native preset): surface `windowBackgroundColor`, raised `controlBackgroundColor`, text three levels, hairline 1 pt (2 pt under Increase Contrast), accent `controlAccentColor` only on the primary Button / active Tab / Switch on / Progress / focus ring, status = system colours with icon + word, type 11…28 pt, space 4 / 8 / 12 / 16 / 20 / 32, radius 7 / 8 / 12, elevation none (elevated variant: one shadow r8 y2), motion 180 ms fade, zero under Reduce Motion. Accessibility: 4.5:1 text and 3:1 accent contrast checked at theme load; visible focus; VoiceOver labels from props; Reduce Motion; Increase Contrast; text size via `controlSize`; never colour alone.

## 3. What json-render is (verified from source, 2026-11-07)

vercel-labs/json-render, Apache-2.0, core 0.22.0, commit 1819412 (2026-11-04). Spec `{ root, elements, state? }`; element `{ type, props, children?, slots?, visible?, on?, repeat?, watch? }`. Expressions `$state $bindState $item $bindItem $index $cond/$then/$else $computed $template` plus custom directives. Visibility: boolean, single (`eq neq gt gte lt lte`, `not`), implicit AND, `$and`, `$or`. Actions: `{ action, params?, confirm?, onSuccess?, onError?, preventDefault? }`; built-ins `setState`, `pushState` (`$id`, `clearStatePath`), `removeState`, `validateForm`. Validation: 13 checks, `validateOn`, `enabled`. Watch: change-only. SpecStream: JSONL of RFC 6902 patches (`add replace remove move copy test`), tolerant `replace`, `\`\`\`spec` fence. Jev: `experimental_composeSpec` (0.21.0+), app-supplied candidates, batched select + arrange, never executes actions. Catalog: `defineCatalog`, `catalog.prompt()`, `catalog.jsonSchema({strict})`, `validateSpec`. 31 skills; install `npx skills add vercel-labs/json-render --skill core`. MCP package serves an HTML iframe (not our path). Shadcn catalog: 36 components.

43 rows in the HTML page. ## 5. Streaming design

`SpecStreamDecoder` (modes `jsonl`, `object` with a tolerant parser for one JSON document in fragments, `mixed` with the spec fence) → `SpecStore` actor (RFC 6902 on immutable `Spec` snapshots, `RenderPlan` diff by id, dangling set) → `FrameCoalescer` (≤ 1 publish per frame, drops intermediates) → `JSONRenderStreamView` (views keyed by element id; themeable skeletons for missing children; out-of-order arrival tolerated; 180 ms fade, none under Reduce Motion; cancellation keeps the last snapshot; malformed lines journaled; final `validateSpec` and prune). Budgets: spec ≤ 256 KiB, 2,000 elements, 64 KiB stream buffer per partial line.

## 6. Nesting design

Depth cap 64, element cap 2,000, 500 rows per repeat; DFS cycle detection per snapshot; children and slots by id; `RepeatScope(item, index, basePath, key)` with nested repeats via `statePath: { "$item": "rows" }`; `$bindItem` → `basePath/field`; action params resolve `$item` to absolute paths at the emitting element's scope; `Spec.compose(child, into:, slot:, prefix:)` for sub-specs; native mapping: Grid → `LazyVGrid`, Card → surface with slots, Tabs → tab bar + subtree, Table → SwiftUI `Table` with cells rendering children under the row scope, Accordion → `DisclosureGroup`, Dialog → host popup surface, Drawer → inspector or sheet.

### 9.5 Optional composer on the OpenAI Decisions API

Verified 2026-11-07: `POST /v1/decisions` exists and is generally available, model `gpt-6-luna` only; request `{ model, input, questions[] }` with question types `predicate`, `choice` (`choices[{value, description}]`), `score` (`levels[{label, description}]`); response `answers[]` with `probability` / `choice` + `probabilities` + `confidence` / `score` + `probabilities` + `confidence`, per-question `refusal`, `usage` with zero output tokens. Sources: the OpenAI guide (developers.openai.com/api/docs/guides/decisions), Microsoft Learn (Azure endpoint `/openai/v1/decisions`, 2026-11-06), and a live probe that read the spike key from the Keychain at run time (never printed or written) and got HTTP 200 in 3.7 s with three typed answers (429 input tokens). Doc-only: 400 questions per request, 128 images / 32 MB, $0.10 per 1M input tokens. Not found: streaming. Unverified: GPT-Live `delegation.type: "decisions"` result delivery (Phase 0 saw nothing in 25 s); the composer calls REST directly.

Design: `CompositionCandidate` (upstream shape), `DecisionEvaluator` protocol (the only network boundary), `OpenAIDecisionsEvaluator`, `Composer.compose(prompt:context:initialSpec:)` → `AsyncThrowingStream<ComposeEvent>`. Round 1 selection in one request (choice "root", one predicate per candidate, score "density" → element budget); round 2 layout in one request (choice "parent/slot" and score "position" per included element); edits sequential with predicates; thresholds 0.5 / 0.35 in `ComposeLimits`; refusals fall back to catalog order; ≤ 3 rounds; never prose or data; props and bindings never sent. Rafu runs it only when the backend calls `compose_view` (decision, revision 4); there is no validation-failure fallback from `show_view`. Key from `KeychainAISecretStore`.

- 10.6 Remote images (revision 4): a global switch in Settings ▸ Ensemble, Off (nothing loads) / Ask (default: trusted hosts load, other hosts need the per-Ensemble consent or the confirm card) / Always allow (any https host, same limits); a domain trust list of host patterns, either an exact host (`images.example.com`) or one leading wildcard (`*.githubusercontent.com`), matched on the parsed URL host after IDNA/punycode normalisation and lowercasing, https only, IP literals, `localhost` and private ranges rejected, never matched on the URL string; the confirm card offers "Allow once", "Always allow images from <host>" and "Always allow *.<registrable parent>" computed from a bundled Public Suffix List (never a bare suffix such as `*.com` or `*.co.uk`); the list lives in `~/Library/Application Support/Rafu/image-trust.json` (per user, 0600, ≤ 200 entries, not in any Ensemble file, not visible to agents); Settings shows the list with add (live validation) and remove; removing a pattern, revoking an Ensemble or switching Off drops the cached images loaded under that grant across open Ensembles; the per-Ensemble consent record `CanvasDocument.permissions.remoteImages { allowed, grantedAt, grantedBy }` stays in the Ensemble file, written only from the confirm card (agents cannot set it); revoke in Ensemble settings and the Agent control popover, undoable; fetch policy https only, GET, no cookies / credentials / Referer, fixed User-Agent, ephemeral session, 8 s, 2 redirects, 2 MB, 20 per card, 4 concurrent, sniffed png/jpeg/webp/gif, SVG refused, private ranges refused; cache decoded at card size (≤ 1,024 px), 8 MB LRU per Ensemble, memory only; privacy sentence in the popup ("The image host will see a request from this Mac."); before consent a placeholder with the host name, the alt text and one button. Package form: `JSONRenderRemoteImages` with `ImageConsent`, `HostPattern` (validator and matcher, pure, Linux-tested), `PublicSuffixProvider` and `RemoteImagePolicy`.
- MDX (decision): `MDXComponentRegistry` and `MDXBlockBuilder` emit `UIElement`s for the Rafu catalog in Phase 4; ADR 0034 amended.

## 11. Build vs borrow
