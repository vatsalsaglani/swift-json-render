Theme

One spec, any look

A theme is a value in the SwiftUI environment. It changes colour, type, space, radius and motion. It never changes what a spec means.

public struct JSONRenderTheme: Sendable, Equatable {
    public var color: ColorRoles        // surface, surfaceRaised, text, textSecondary, textMuted, hairline, accent, onAccent, good, warning, critical, info, focus
    public var type: TypeScale          // caption, footnote, body, bodyEmphasis, title, display; weights; mono
    public var space: SpaceScale        // s1...s6
    public var radius: RadiusScale      // control, field, card
    public var elevation: Elevation     // card shadow for the elevated variant only
    public var motion: Motion           // reveal, pulse; honours accessibilityReduceMotion
    public var charts: ChartTokens      // categorical, sequential and diverging ramps, gridline, widths
    public static let native: JSONRenderTheme
    public static let highContrast: JSONRenderTheme
    public func validated() throws(ThemeContrastError) -> JSONRenderTheme   // 4.5:1 text, 3:1 accent
}

Six layers, least to most effort

A host picks the lowest layer that does the job. Each layer has one API.

Rule. Customisation never changes semantics. Layers a to f receive resolved props, bindings, children and emit. None can change state paths, action names, validation, visibility or the order of children. The parity suite runs once per preset, and once with every type overridden by a stub, and asserts the same state transitions and actions.

a

Theme tokens

Colour roles, type scale, spacing, radius, elevation and motion, as one JSONRenderTheme value. Presets: .native, .rafuIndigo, .rafuKhadi, .highContrast. Per-subtree overrides compose.

JSONRenderView(spec: spec, catalog: .standard)
    .jsonRenderTheme(.rafuIndigo)                       // whole view
    .jsonRenderTheme(\.radius.card, 6)                  // one token
    .jsonRenderTheme(.highContrast, forTypes: ["Alert"]) // one subtree by type

b

Variants and sizes in the catalog

Looks the model may pick, declared as enum props. The theme decides what a variant looks like; the model only names it.

Button: .component(
    props: [
        "label": .string(),
        "variant": .enum(["primary", "secondary", "destructive", "plain"], default: "secondary",
                         description: "Use primary for the one main action."),
        "size": .enum(["sm", "md", "lg"], default: "md"),
    ],
    events: ["press"])
Card: variant plain | outlined | elevated      // default outlined
c

Per-type style hooks

A SwiftUI style protocol per component, the same shape as ButtonStyle. The host restyles without touching behaviour. The configuration carries resolved props and state flags, never the state store.

public protocol JRCardStyle {
    associatedtype Body: View
    func makeBody(configuration: JRCardStyleConfiguration) -> Body
}
public struct JRCardStyleConfiguration {
    public let title: Text?; public let description: Text?
    public let variant: JRCardVariant; public let content: JRStyleContent
    public let isStreaming: Bool
}
JSONRenderView(...).jrCardStyle(RafuCardStyle())   // also jrTabsStyle, jrTableStyle, jrLinkStyle ...

Slots

json-render's slots field with a fixed vocabulary: header, footer, leading, trailing, empty, loading, error. A slot is a list of element ids.

{ "type": "Card", "props": { "title": "Failures" },
  "children": ["table"],
  "slots": { "footer": ["rerun", "open"], "empty": ["none-text"] } }

Full view replacement per type

Replace the view for one type and keep its props schema, bindings, children and actions. Both tables below share one state. Dismiss a row in either and both change.

var catalog = try Catalog.standard
try catalog.override("Table") { context in
    AnyView(RafuTable(context: context))   // same props, same events: use context.emit

Custom components and actions

Add new types and actions with one macro or one closure. The macro writes the prop schema, the description for the prompt, and the JSON Schema entry. Hosts can also register functions for $computed and directives.

@JRComponent("TerminalStatus", description: "Live status of one Ensemble terminal", events: ["open"])
struct TerminalStatusView: View {
    @JRProp(description: "Terminal node id") var node: String
    @JRProp var title: String = ""
    @JRProp(bindable: true) var pinned: Bool = false
    var body: some View { /* ... */ }
}
try catalog.register(TerminalStatusView.self)
catalog.action(
    "open_file", params: .object([.init(name: "path", schema: .string)]),
    description: "Open a file in the editor"
) { params, host in
    // Runs only because the app registered it. A spec cannot add an action.
    return nil
}
